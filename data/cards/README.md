# Card data

Three JSON files, generated by `ml/scripts/fetch_cards.py` and hand-edited only for variant
overrides. The app bundles them at build time (Xcode "Bundle card data" phase), and
`swift test` validates them (`RepoDataTests`), so a broken reference fails the tests.

| File | One entry per | Key fields |
| --- | --- | --- |
| `cards.json` | card number (`OP05-119`) | TCG stats, `characterId`, `defaultVariantId` |
| `printings.json` | physical print (base, parallel, manga, promo) | `artCrop`, `embeddingRow`, `variantId` override |
| `variants.json` | character form (`luffy_gear4`) | `modelAsset`, `heightMeters`, `animations` |

Resolution: printing `variantId` if set, else the card's `defaultVariantId`.

**The seed entries are placeholders** copied from the spec's illustrative JSON. Card names,
stats, rarities, and which art shows which form are unverified. Check them against the
OPTCG API before you finalize the roster, and pick the real three cards (two forms of one
character plus one distinct character).

## Beside the JSON (gitignored)

- `printings.f32`: reference embeddings, flat little-endian float32, row-major, one row per
  printing. The row count is `max(embeddingRow) + 1` and the dimension is inferred from the file
  size. If present, it is bundled and used instead of computing embeddings on the device. See
  `docs/cv-pipeline.md` for the contract.
- `art/`: downloaded card images.
